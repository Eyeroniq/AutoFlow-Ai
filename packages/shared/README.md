# @flowforge/shared

TypeScript types generated from the backend's OpenAPI document, so the web app doesn't keep a second,
hand-written copy of every API model that can drift.

| File | What |
| --- | --- |
| `openapi.json` | The API's OpenAPI document (`python -m app.openapi_export`), committed |
| `src/api.ts` | Generated by [openapi-typescript](https://openapi-ts.dev) from `openapi.json`: `paths`, `components`, `operations`. **Don't edit** |
| `src/index.ts` | `Schemas = components["schemas"]` and re-exports |

Types only: nothing in this package runs, and the web app imports it with `import type`.

```bash
scripts/generate-shared-types.sh      # export the spec from the running API, regenerate src/api.ts
```

Commit both generated files. The backend test `test_shared_openapi_is_current` fails when `openapi.json`
no longer matches the API, so a changed schema can't ship with stale web types.

The web app resolves `@flowforge/shared` through a `paths` alias in `apps/web/tsconfig.json`
(`../../packages/shared/src/index.ts`; the `web` Compose service mounts this folder at `/packages/shared`).
`apps/web/src/lib/types.ts` aliases the generated schemas (`export type User = Schemas["UserRead"]`) and
keeps hand-written types only where the API doesn't describe the shape (WebSocket events, JSON Schema).
